## 1. Verifier ablation (MuJoCo, the main result)

**Question.** When execution can fail, how much does verifying from camera pixels raise task success, and how much more does feeding the measured error back into the retry add?

**Design.** Three tasks (pick-and-place, stack, two-step) on seeded random scenes; four fault profiles injected into the arm (`env/faults.py`); five arms sharing identical attempt-1 faults per seed; attempt budget 3; success scored by simulator ground truth at episode end. Comparisons are paired by seed (exact McNemar). Reproduce: `python -m bench.run --episodes 30`, then `python -m bench.report`.

_30 seeds per cell, attempt budget 3; success = simulator ground truth at episode end; brackets are 95% Wilson intervals; 0 episodes errored._

## 4. ManiSkill3 (standard benchmark)

`PickCube-v1` in the `docker/maniskill` image (CPU simulation, software Vulkan rendering), 30 seeds per cell, attempt budget 3, the environment's own `success` metric. The cube is localised from the RGB-D camera (red colour mask + depth, about 2 mm error in the probe); ManiSkill's mplib motion planner executes; the same fault profiles (grasp/release noise, constant release bias) are injected. The goal position is the task specification.

| Fault profile | No verifier | Verifier + blind retry | Verifier + corrected retry |
|---|---|---|---|
| nominal | 30/30 = 100% [89-100], 0 false-ok | 28/30 = 93% [79-98], 0 false-ok | 27/30 = 90% [74-97], 0 false-ok |
| noisy | 8/30 = 27% [14-44], 22 false-ok | 12/30 = 40% [25-58], 2 false-ok | 9/30 = 30% [17-48], 1 false-ok |
| biased | 0/30 = 0% [0-11], 30 false-ok | 0/30 = 0% [0-11], 0 false-ok | 25/30 = 83% [66-93], 0 false-ok |

Paired exact McNemar (episodes only the first arm solved vs only the second):

- nominal, verifier_blind vs no_verifier: 0 vs 2 (p=0.5)
- nominal, verifier_corrected vs verifier_blind: 0 vs 1 (p=1)
- noisy, verifier_blind vs no_verifier: 6 vs 2 (p=0.289)
- noisy, verifier_corrected vs verifier_blind: 2 vs 5 (p=0.453)
- biased, verifier_blind vs no_verifier: 0 vs 0 (p=1)
- biased, verifier_corrected vs verifier_blind: 25 vs 0 (p=5.96e-08)

**Honest limitation.** With no faults the camera-verifier arms lose 2-3 of 30 episodes that the no-verifier arm wins. The cause is occlusion: PickCube holds the cube in the air at the goal, the gripper hides it from the fixed camera, and the verifier reports "cube not visible" (a false reject) and retries. The MuJoCo study avoids this by moving the arm out of view before each look; this task cannot. Noisy-profile gains (27% to 40%) are not statistically significant at n=30.
